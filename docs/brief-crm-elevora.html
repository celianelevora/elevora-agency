Brief CRM Elevora

Le prompt intégral à donner à Claude Code (Opus 5) pour auditer, réparer et faire évoluer le CRM interne. Écrit d'après une lecture complète du code déployé.

Cible : Claude Code · Opus 5 Effort recommandé : xhigh Base analysée : 28 500 lignes Lots : phase 0 + 10

Comment s'en servir

  1. Décompresse crm-admin.elevora-agency.com.zip dans un dossier, et fais-en un dépôt git (git init && git add . && git commit) — le prompt s'appuie sur des commits incrémentaux.
  2. Lance Claude Code dans ce dossier, pas à la racine de elevora-agency : le CRM est un projet à part (HTML/PHP vanilla), et le CLAUDE.md global impose Next.js — il ne doit pas s'appliquer ici.
  3. Règle le modèle sur Opus 5 et l'effort sur xhigh.
  4. Clique sur Copier le prompt ci-dessous et colle-le en premier message. En un seul bloc : Opus 5 travaille nettement mieux avec la spécification complète en entrée qu'avec des consignes distillées tour par tour.

À joindre au message

Deux fichiers, en pièce jointe ou déposés dans le dossier : le zip du CRM décompressé, et l'export du schéma Supabase (Supabase Snippet Untitled query.csv). Le message d'erreur de la création de compte est déjà intégré au prompt, tu n'as rien à recopier. Si tu as une capture de la vue d'ensemble actuelle, joins-la aussi — elle aide, sans être nécessaire.

Ce que le prompt demande, en quinze lignes

Pour ne pas avoir à lire les 60 000 caractères.

  • Phase 0 — lire tout le code, cartographier, détecter les boutons morts et les appels API fantômes, tester chaque écran dans un navigateur, produire AUDIT.md chiffré, corriger, et me donner le nombre de bugs corrigés. Plus schema-complet.sql (toutes les tables Supabase, à recoller) et CRONS.md (les quatre tâches planifiées à créer).
  • Lot 1 · Vue d'ensemble — cinq nouveaux chiffres centrés sur les clients qu'on a. Zéro conversion, zéro perdus. Les camemberts partent, de vraies courbes arrivent, grille bento au lieu d'une colonne.
  • Lot 2 · Comptabilité — le gros morceau : réparer l'entrée des mouvements Qonto, catégorisation qui apprend, apports des associés hors CA, rapprochement par IBAN avec paiements partiels et ordre des factures, TVA réelle avec exceptions, détection des récurrences, échéancier fiscal, synchro automatique par cron.
  • Lot 3 · Équipe — corriger la création de compte, avec le protocole de diagnostic à suivre.
  • Lot 4 · Étapes de paiement — l'échéancier du contrat génère les étapes de paiement dans la liste des étapes du projet.
  • Lot 5 · Visuel — plus aucun emoji, bouton de téléchargement refait.
  • Lot 6 · Notifications — regroupement par client, catégories métier, fin de vie automatique, anti-doublon.
  • Lot 7 · Historique — vue jour / semaine / mois et chargement progressif.
  • Lot 8 · Suppressions — export CSV de Rapports, tuile CA potentiel, indicateurs de conversion, emojis, sélecteur de modèle.
  • Lot 9 · Signaux — comprendre pourquoi « Rien d'urgent », ajouter huit règles, et faire en sorte que le moteur signale ses propres pannes.
  • Lot 10 · Modèle IA — tout sur Haiku, plus de choix dans l'interface, sorties structurées pour fiabiliser.
